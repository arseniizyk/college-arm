# План устранения UI/UX проблем (ui-issues.md)

Документ фиксирует пошаговый план исправления 43 проблем интерфейса и пользовательского опыта, выявленных в ходе UI/UX аудита ([`ui-issues.md`](./ui-issues.md)).

---

## 1. Регламент и архитектурные рамки

- **Область изменений:** исключительно клиентская часть (`client/`). Изменения на стороне сервера (`server/`) не требуются — API и шаблоны генерации документов остаются нетронутыми.
- **Среда развертывания:** проект запускается и тестируется в Docker Compose.
- **Процесс итерации:**
  1. Выполнение доработок в рамках фазы.
  2. Запуск автоматических тестов (`npm test` в `client/`) и проверка сборки.
  3. Пересборка и запуск контейнера клиента:
     ```bash
     docker compose up -d --build client
     ```
  4. Ручная проверка пользователем в браузере по адресу `http://localhost:8080` (порт из `.env` `CLIENT_PORT`).
  5. Переход к следующей фазе после подтверждения.

---

## 2. Фазы реализации

### Фаза 1: Дизайн-система, иконографика и визуальный стиль [ЗАВЕРШЕНА]

**Цель:** устранить визуальный шум, стандартизировать дизайн-токены, искоренить битые иконки и удалить зависимость от внешнего CDN Font Awesome.

**Решаемые пункты из `ui-issues.md`:**
- **5.1:** Единая система CSS-токенов в `:root` (`client/src/index.css`) — палитра, тени, радиусы, типографика. Устранение дублирования переменных в `Main.css`, `Admin.css`, `Request.css`, `Profile.css`.
- **5.2:** Унификация радиусов скруглений (базовый радиус 8px / `0.5rem`) для кнопок, карточек и полей ввода во всех модулях.
- **5.3:** Полный аудит и нормализация иконок:
  - Удаление CDN Font Awesome из `client/public/index.html`.
  - Исправление несуществующих/битых классов: `bi-persons` → `bi-people`, `bi-trash-alt` → `bi-trash`, `bi-calendar-alt` → `bi-calendar3`, `bi-person-graduate` → `bi-mortarboard`, `bi-person-slash` → `bi-person-x`, `bi-check-lg-circle` → `bi-check-circle`.
  - Замена Font Awesome классов размеров (`fa-2x`, `fa-3x`) на классы Bootstrap (`fs-1`–`fs-3`) или CSS.
  - Семантическое разделение метафор («Пользователи» → `bi-person-circle`, «Группы» → `bi-collection`).
  - Устранение иконочного шума перед каждым обычным текстовым полем в `Request.jsx` и `Profile.jsx`.
  - Замена хардкода Font Awesome в `Privacy.css`.
- **7.1:** Отказ от устаревших тяжелых синих градиентов и радиальных пятен в шапках страниц в пользу чистого современного фона (`#f8fafc` / `#ffffff`) и аккуратных плоских акцентов.
- **7.2:** Замена «грязных» жестких теней (`rgba(0,0,0,0.2)`) на мягкую многоуровневую шкалу теней.
- **7.3:** Унификация цветовой семантики статусов заявок (`pending` / `completed` / `rejected`) в `requestStatus.js`, карточках и статистике.
- **7.5:** Перенос инлайн JS-стилей ховеров (`onMouseEnter` / `onMouseLeave`) в декларативные CSS-классы.

**Основные файлы:**
- `client/public/index.html`
- `client/src/index.css`
- `client/src/pages/Main.css`, `Admin.css`, `Request.css`, `Profile.css`, `Privacy.css`
- `client/src/utils/requestStatus.js`
- `client/src/components/MultiselectStudents.jsx`, `RequestCard.jsx`, `CRUDModal.jsx`, `DocumentsGeneration.jsx`

**Критерии приемки:**
- Отсутствуют пустые места вместо иконок.
- Во всех разделах интерфейса кнопки и карточки имеют согласованные скругления и мягкие тени.
- В шапках страниц нет пятнистых радиальных градиентов.
- Сеть не запрашивает файлы Font Awesome.

### Фаза 2: Доступность (a11y), интерактивность и валидация форм [ЗАВЕРШЕНА]

**Цель:** обеспечить поддержку клавиатурной навигации, корректные ARIA-атрибуты, удобный выбор дат в приказах и согласованную валидацию форм.

**Решаемые пункты из `ui-issues.md`:**
- **3.1:** Унификация клиентской валидации через Bootstrap-паттерны (`was-validated` / `isInvalid` с `<Form.Control.Feedback>`) вместо несогласованных нативных браузерных всплывающих подсказок.
- **3.2:** Замена ручного текстового ввода дат в модальных окнах приказов (включая `PracticeContractModal.jsx`) на стандартные контролы выбора дат (`type="date"`) с автоматическим формированием текстовых строк, требуемых шаблонами.
- **3.3:** Защита от случайного или двойного удаления критических сущностей в `CRUDModal.jsx` (состояние подтверждения / явный дизейбл повторного клика).
- **6.1:** Интерактивные элементы на `div` (раскрытие карточек заявок, выбор студентов) снабжаются `role="button"`, `tabIndex={0}`, `aria-expanded` и поддержкой клавиш `Enter` / `Space`.
- **6.2:** Устранение проблем контрастности вторичного текста (`text-muted` на светло-сером фоне) в соответствии с WCAG 2.1 AA (контраст ≥ 4.5:1).
- **7.4:** Увеличение минимального размера кнопок действий в строках таблиц до 36×36px (с безопасными отступами между редактированием и удалением) по закону Фиттса.

**Основные файлы:**
- `client/src/components/TableContent.jsx`
- `client/src/components/CRUDModal.jsx`
- `client/src/components/PracticeContractModal.jsx`, `BaseOrderModal.jsx`, модальные окна приказов
- `client/src/components/RequestCard.jsx`
- `client/src/components/MultiselectStudents.jsx`

**Критерии приемки:**
- Карточки заявок и элементы выбора раскрываются и активируются с клавиатуры (Tab + Enter/Space).
- Модалки приказов предлагают календарный выбор дат без ручного набора строк вида «30 января 2023 г.».
- При некорректном заполнении форм подсвечиваются аккуратные inline-ошибки Bootstrap, без серых браузерных тултипов.
- Кнопки действий в таблицах удобны для клика и не сжимаются до микроскопических размеров.

### Фаза 3: Адаптивность и мобильный интерфейс [ЗАВЕРШЕНА]

**Цель:** сделать интерфейс полностью функциональным на смартфонах и планшетах без горизонтального расползания и раздутия высоты строк.

**Решаемые пункты из `ui-issues.md`:**
- **1.1:** Адаптивное отображение таблиц админ-панели на экранах < 768px: горизонтальный скролл с читаемыми размерами шрифтов, `min-width: 650px`, зафиксированными действиями в строку и отсутствием раздутия высоты строк.
- **1.2:** Рефакторинг `SearchAndFilters.jsx`: удаление жестких инлайн-ширин (`700px`/`300px`), переход на адаптивную сетку Bootstrap (`row g-2`, `col-12 col-sm-6...`), адаптивное растяжение поля поиска по email на всю ширину на мобильных устройствах.
- **1.3:** Мобильный лейаут модальных окон: добавление `scrollable` для `Modal`, стилизация `.modal-dialog-scrollable .modal-content > form`, flex-структура формы и `overscroll-behavior: contain` для изолированной прокрутки содержимого формы без скролла заднего фона страницы.
- **1.4:** Оптимизация мобильного меню `Offcanvas` в `NavBar.jsx`: устранение двойного скролла в блоке уведомлений (скролл ограничен списком `.notification-list` с `max-height: 220px`), предотвращение выталкивания кнопок профиля и выхода за пределы экрана смартфона.
- **Дополнительно:** 
  - Главные вкладки админ-панели (`.main-admin-tabs`) перестроены в адаптивную сетку 2×2 / 1×1 на планшетах и мобильных вместо хаотичного переноса.
  - Устранено вертикальное покачивание вкладок (`overflow-y: hidden !important` для `.nav-tabs`).
  - Выровнены кнопки пагинации «Назад» и «Вперед» через единый `flex-wrap gap-2` без асимметричных марджинов.

**Основные файлы:**
- `client/src/components/TableContent.jsx`
- `client/src/pages/Admin.css`
- `client/src/pages/Admin.jsx`
- `client/src/components/SearchAndFilters.jsx`
- `client/src/components/Pagination.jsx`
- `client/src/components/CRUDModal.jsx`, `BaseOrderModal.jsx`, модалки приказов
- `client/src/components/NavBar.jsx`, `NavBar.css`
- `client/src/index.css`

**Критерии приемки:**
- При ширине экрана 375px–768px админ-панель не разваливается, данные читаемы, кнопки действий доступны.
- Формы в модальных окнах прокручиваются внутри тела модалки, фоновая страница не скроллится, кнопки «Сохранить» / «Отмена» всегда видны внизу экрана.
- Мобильное меню навигации компактно и позволяет перейти в профиль или выйти из системы без бесконечной прокрутки списка уведомлений.

### Фаза 4: Система обратной связи (Feedback & Status) и пустые состояния [ЗАВЕРШЕНА]

**Цель:** предоставить пользователю прозрачную индикацию длительных операций, фоновых обновлений и понятные точки входа при пустых данных.

**Решаемые пункты из `ui-issues.md`:**
- **2.1:** Ненавязчивая визуализация фоновой синхронизации данных (тихий поллинг раз в 60 секунд) без рывков контента.
- **2.2:** Индикация длительного процесса формирования и скачивания Word-документов (`RequestCard.jsx`, модалки приказов) с уведомлением о начале и завершении загрузки.
- **2.3:** Замена 5-секундных исчезающих таймеров `setTimeout` на плавающий стек Toast-уведомлений с возможностью ручного закрытия.
- **2.4:** Информативные пустые состояния (Empty States) с иконкой, пояснением и кнопкой первичного действия (Primary CTA, например, «Подать заявку» на `/request`) в профиле и таблицах.

**Основные файлы:**
- `client/src/components/ToastContainer.jsx` (или внедрение системы тостов)
- `client/src/components/RequestCard.jsx`
- `client/src/pages/Request.jsx`, `Profile.jsx`
- `client/src/components/TableContent.jsx`
- `client/src/components/BaseOrderModal.jsx`

**Критерии приемки:**
- При скачивании справок или формировании приказов пользователь видит четкий статус процесса.
- Сообщения об успешном создании заявки или смене пароля не исчезают бесследно, пока пользователь их не прочитает/закроет.
- В пустых вкладках («Нет заявок») отображается кнопка быстрого перехода к созданию заявки.

### Фаза 6: Сортировка данных в таблицах (Table Sorting) [СЛЕДУЮЩАЯ К ВЫПОЛНЕНИЮ]

**Цель:** предоставить возможность интерактивной сортировки строк по столбцам (по возрастанию и убыванию) во всех административных таблицах данных.

**Задачи:**
- Интеграция состояния сортировки (`sortConfig`: `{ key, direction: 'asc' | 'desc' | null }`) в хук `useAdminLogic.js`.
- Реализация функции сортировки с поддержкой:
  - Текстовых полей (по алфавиту с учетом русской локали `localeCompare`);
  - Числовых полей и идентификаторов;
  - Дат (хронологический порядок);
  - Вычисляемых полей и связанных сущностей (ФИО студента, название группы, специальность, статус).
- Обновление компонента заголовков таблицы (`TableContent.jsx`):
  - Кликабельные заголовки сортируемых колонок с курсором `pointer`;
  - Наглядные индикаторы направления сортировки (`bi-arrow-down-up` для нейтрального, `bi-arrow-up` для ASC, `bi-arrow-down` для DESC);
  - Атрибуты доступности `aria-sort` (`ascending`, `descending`, `none`).
- Корректная связка с пагинацией: сортировка всего отфильтрованного массива данных перед вычислением среза текущей страницы (`slice`).

**Основные файлы:**
- `client/src/hooks/useAdminLogic.js`
- `client/src/components/TableContent.jsx`
- `client/src/components/DataManagement.jsx`
- `client/src/utils/tableConfig.js`
- `client/src/pages/Admin.css`

**Критерии приемки:**
- Клик по заголовку столбца сортирует данные по возрастанию, повторный клик — по убыванию, третий клик сбрасывает сортировку к исходному порядку.
- Отображаются понятные стрелочки направления сортировки рядом с названием столбца.
- Сортировка корректно работает совместно с поиском, фильтрами по группам/специальностям/ролям и постраничной навигацией.
