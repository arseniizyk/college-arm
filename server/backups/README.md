# Система автоматических бэкапов базы данных

## Описание

Система автоматически создает резервные копии базы данных PostgreSQL каждый день в 3:00 ночи (по времени Минска).

## Настройка

### Переменные окружения (.env)

```env
# Расписание создания бэкапов (cron формат)
# По умолчанию: каждый день в 3:00
BACKUP_SCHEDULE=0 3 * * *

# Создавать ли бэкап при запуске сервера
BACKUP_ON_START=false
```

### Формат cron расписания

```
* * * * *
│ │ │ │ │
│ │ │ │ └─ День недели (0-7, 0 и 7 = воскресенье)
│ │ │ └─── Месяц (1-12)
│ │ └───── День месяца (1-31)
│ └─────── Час (0-23)
└───────── Минута (0-59)
```

Примеры:
- `0 3 * * *` - каждый день в 3:00
- `0 */6 * * *` - каждые 6 часов
- `0 0 * * 0` - каждое воскресенье в полночь

## API эндпоинты (только для администраторов)

### Создать бэкап вручную
```
POST /api/backup/create
Authorization: Bearer <admin_token>
```

### Получить список бэкапов
```
GET /api/backup/list
Authorization: Bearer <admin_token>
```

### Скачать бэкап
```
GET /api/backup/download/:fileName
Authorization: Bearer <admin_token>
```

### Восстановить из бэкапа
```
POST /api/backup/restore
Authorization: Bearer <admin_token>
Content-Type: application/json

{
  "fileName": "backup_2024-02-26.sql"
}
```

## Хранение бэкапов

- Бэкапы хранятся в директории `server/backups/`
- Автоматически сохраняются последние 7 бэкапов
- Старые бэкапы удаляются автоматически
- Формат имени файла: `backup_YYYY-MM-DD.sql`

## Требования

- PostgreSQL должен быть установлен на сервере
- Утилита `pg_dump` должна быть доступна в PATH
- Для восстановления требуется утилита `psql`

## Установка зависимостей

```bash
cd server
npm install
```

Пакет `node-cron` будет установлен автоматически.

## Запуск

При запуске сервера планировщик бэкапов запускается автоматически:

```bash
npm run server
```

В консоли вы увидите:
```
[BACKUP SCHEDULER] Планировщик запущен. Расписание: 0 3 * * *
[BACKUP SCHEDULER] Бэкапы будут создаваться каждый день в 3:00
```

## Логи

Все операции с бэкапами логируются в консоль:
- `[BACKUP]` - операции создания/восстановления бэкапов
- `[BACKUP SCHEDULER]` - работа планировщика

## Безопасность

- Все операции с бэкапами доступны только пользователям с ролью `ADMIN`
- Пароль базы данных передается через переменную окружения `PGPASSWORD`
- Файлы бэкапов хранятся локально на сервере

## Восстановление базы данных

⚠️ **ВНИМАНИЕ**: Восстановление из бэкапа перезапишет текущие данные!

1. Получите список доступных бэкапов через API
2. Выберите нужный бэкап
3. Отправьте запрос на восстановление
4. Дождитесь завершения операции

## Ручное создание бэкапа

Вы можете создать бэкап вручную в любое время через API эндпоинт `/api/backup/create`.
