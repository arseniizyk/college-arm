# Дипломный проект — автоматизация документооборота колледжа

Два независимых приложения без корневого `package.json` и без git-репозитория.

```
client/  React 19 + CRA (react-scripts 5) + MobX + react-bootstrap
server/  Express 4 (CommonJS) + Sequelize + PostgreSQL + docx
```

## Запуск

```bash
cd server && npm install && npm run server   # nodemon index.js, порт 7000
cd client && npm install && npm start        # CRA dev server, строго localhost:3000
```

Перед запуском нужны `server/.env` и `client/.env` (шаблон — `server/.env.example`).
PostgreSQL слушает порт **1111**, а не 5432.

## Заполнение базы тестовыми данными

Чтобы не заполнять базу вручную, есть `server/seed.js`. Он создаёт специальности,
группы, кураторов, студентов, заявки с уведомлениями и аккаунты всех трёх ролей
вместе с первым `ADMIN` (через API его создать нельзя — регистрация выставляет
`role: 'USER'`).

```bash
cd server
npm run seed -- --force
```

**Ключевое:** без флагов скрипт **ничего не удаляет**. Если в базе уже есть записи,
он покажет текущие счётчики и откажется работать — чтобы один запуск не стёр
реальные данные.

| Команда | Что делает |
|---|---|
| `npm run seed` | Проверяет базу. Пустая — заполняет; непустая — отказывается и печатает счётчики |
| `npm run seed -- --force` | **Очищает все таблицы** и заполняет заново |
| `npm run seed -- --keep` | Дозаполняет, не трогая существующие записи |
| `npm run seed -- --students=200 --groups=20` | Свой объём данных |
| `npm run seed -- --seed=42` | Другой набор псевдослучайных данных (см. ниже) |

Ключи объёма: `--specialties`, `--groups`, `--students`, `--teachers`, `--requests`.
Аргументы идут после `--`, иначе npm их не передаст.

### Вход в систему

Пароль у всех созданных аккаунтов — `password123`.

| Email | Роль | Что проверяет |
|---|---|---|
| `admin@test.ru` | `ADMIN` | Админка целиком, все приказы, доступ ко всем студентам |
| `teacher1@test.ru` | `TEACHER` | Ограничение на свою группу (B12) |
| `user1@test.ru` | `USER` | Заявка только на привязанного студента (B1) |
| `teacher.no-link@test.ru` | `TEACHER` | Аккаунт не назначен куратором: в форме заявки ожидается сообщение, а не пустой список |
| `user.no-link@test.ru` | `USER` | Аккаунт без привязанного студента: то же |

### Намеренно сломанные записи

Две группы данных создаются «неправильными» — чтобы было что проверять, а не
заниматься ручной порчей состояния:

- **Группа `99-99-99` без специальности** + 3 студента и заявка на справку по ним.
  Так выглядит результат удаления специальности из UI: FK `groups.specialtyId`
  объявлен как `ON DELETE SET NULL`, и группы остаются. Справка по такой заявке
  должна вернуть 400 с перечнем студентов (раньше приходил пустой валидный .docx
  на 7 КБ с кодом 200). В таблице групп такая строка помечена «Без специальности»
  и видна по одноимённому фильтру. См. **B5** в [issues.md](issues.md).
- **Аккаунты без привязки** — см. таблицу выше.

### Детерминированный набор

Генератор псевдослучайных чисел с фиксированным сидом (по умолчанию `--seed=20260930`):
повторный запуск с теми же аргументами даёт тот же набор данных. Это нужно, чтобы
сравнивать скриншоты админки между прогонами. Указывайте `--seed=N`, если нужен другой
набор, и тот же `--seed`, если хотите его воспроизвести.

### На заметку

Скрипт вызывает `sequelize.sync()` **без** `alter: true` — он создаёт недостающие
таблицы, но не меняет структуру существующих. Изменения схемы по-прежнему приходят
из `server/index.js` (см. **B6** в [issues.md](issues.md)).

## Известные проблемы

- `server/.env` содержит испорченный русский текст в `COLLEGE_NAME` / `DIRECTOR_NAME`
  (двойное кодирование, не восстанавливается) — все документы выходят сgarbled-именами.
- 18 мест в клиенте используют сырой `fetch()` с хардкодом `localhost:5000`, тогда как
  сервер работает на 7000; работают только благодаря `REACT_APP_API_URL` в `client/.env`.
- `GET /api/supervisor` в `DataStore` не имеет серверного маршрута — `loadAllData()`
  всегда даёт один 404.
- Миграций нет: `server/index.js` выполняет `sequelize.sync({ alter: true })` при каждом
  запуске, то есть правка моделей — это немедленный DDL на боевой базе.
- Первого `ADMIN` невозможно создать через API (регистрация жёстко выставляет
  `role: 'USER'`) — нужен либо `server/seed.js` (он создаёт админа сам), либо прямой
  `UPDATE "user" SET role='ADMIN'`.
- Роль зашита в JWT — смена роли в БД не действует до повторного входа.
- `server/utils/backupScheduler.js` запускается при каждом старте: при
  `BACKUP_ON_START=true` полный `pg_dump` блокирует запуск. Cron жёстко привязан к
  `Europe/Minsk`, хранится 7 последних дампов.

Подробности — в [issues.md](issues.md).

## Соглашения

- Текст интерфейса, сообщения API и комментарии — **на русском**.
- Сервер — CommonJS, клиент — ESM/JSX. Расширения файлов не менять (`.js` / `.jsx`).
- Ошибки сигнализируются фабриками `server/error/ApiError.js`;
  `ErrorHandlingMiddleware` остаётся последним зарегистрированным middleware.
- Скрипты чата: `cd server && npm run server`, `cd client && npm start`,
  `cd server && npm run seed` (тестовые данные).
- Тестов в репозитории нет; единственная автопроверка — ESLint в составе CRA
  (`npm start` / `npm run build`).
